# REACTOR — 온라인 멀티플레이 게임 플랫폼

브라우저에서 돌아가는 멀티플레이 게임 모음입니다. 첫 타이틀은 **아레나 FPS**이고,
같은 서버·프로토콜 구조 위에 체스와 테트리스 대결을 얹을 수 있게 설계했습니다.

- **클라이언트**: TypeScript + three.js (WebGL2, PBR + 실시간 그림자 + 포스트프로세싱)
- **서버**: Cloudflare Workers + Durable Objects (권위 서버, 64Hz 시뮬레이션)
- **네트워크**: WebSocket 바이너리 프로토콜, 클라이언트 예측 + 서버 재조정 + 지연 보상
- **봇**: 자동 생성 내비게이션 그래프로 길을 찾고 엄폐물을 쓰는 AI — 방이 절대 비지 않습니다

---

## 클라우드플레어로 되나?

**됩니다.** 방(room) 하나당 Durable Object 하나를 띄우고, 그 안에서 64Hz 게임 루프를
돌리면서 WebSocket으로 스냅샷을 뿌리는 구조입니다. DO는 싱글스레드 + 단일 인스턴스가
보장되므로 권위 서버로 쓰기에 잘 맞고, 전 세계 엣지에서 실행되니 별도 리전 관리도
필요 없습니다. SQLite 백엔드 Durable Objects는 Workers 무료 플랜에서도 쓸 수 있습니다.

다만 한계는 분명히 알고 시작하는 게 좋습니다.

| 항목 | 상황 |
| --- | --- |
| 전송 | WebSocket(TCP)만 가능. UDP·WebTransport·WebRTC DataChannel은 Workers에서 못 씀 |
| 영향 | 패킷 손실 시 head-of-line blocking → 아주 드물게 순간 끊김. 30Hz 스냅샷·작은 패킷이라 실사용엔 무난 |
| 규모 | 6~12인 아레나에 적합. 100인 배틀로얄이나 프로 경쟁전 수준은 전용 UDP 서버(게임 서버 VM)가 필요 |
| 체스·테트리스 | 턴제/저빈도라 오히려 이상적. 같은 DO 구조 그대로 재사용 가능 |

즉 **지금 목표(퀄리티 있는 캐주얼~미들코어 멀티)에는 클라우드플레어가 정답에 가깝고**,
나중에 진짜 하드코어 경쟁 FPS로 간다면 그때 전송 계층만 갈아끼우면 됩니다. 게임 로직은
`packages/shared`에 모여 있어서 서버 런타임 교체 비용이 크지 않습니다.

## 구조

```

  room.ts              권위 매치 전체 (전송 계층 비의존) — DO와 브라우저가 같은 코드를 실행
  bot.ts               봇 AI: 타깃 선정, 조준 지연/오차, 버스트 사격, 교전 중 스트레이핑
  nav.ts               충돌 지오메트리에서 자동 생성하는 다층 내비게이션 그래프
  constants.ts         틱레이트, 이동 상수 — 양쪽이 반드시 같은 값을 써야 함
  movement.ts          Quake/Source 스타일 이동 (예측·재조정의 기준)
  collision.ts         브러시 AABB 스윕 + 레이캐스트 (XZ 그리드 broadphase)
  map.ts               레벨을 브러시 배열로 정의 (서버도 같은 지오메트리로 충돌 계산)
  hitbox.ts            머리/몸통/다리 히트박스
  weapons.ts           무기 스탯 (연사, 데미지, 반동, 탄퍼짐, 거리감쇠)
  protocol.ts          바이너리 인코딩/디코딩

apps/server/         Cloudflare Worker
  index.ts             퀵매치/방 API, /ws 업그레이드, 정적 파일 서빙
  GameRoom.ts          Durable Object 래퍼 — 틱 타이머와 WebSocket 브리지가 전부 (95줄)

apps/client/         Vite + three.js
  net/Connection.ts    소켓, 스냅샷 버퍼, RTT 측정
  net/LocalConnection.ts  같은 탭에서 MatchRoom을 호스팅하는 오프라인 모드
  game/Game.ts         메인 루프, 예측/재조정, 원격 플레이어 보간
  game/Renderer.ts     하늘·IBL·그림자·블룸·컬러그레이딩
  game/Materials.ts    절차적 PBR 텍스처 (에셋 파일 0개)
  game/LevelBuilder.ts 브러시 → 머티리얼별 단일 메시로 병합 (드로우콜 ~5)
  game/ViewModel.ts    1인칭 무기 (반동/스웨이/보빙/ADS/재장전)
  game/CharacterModel.ts  절차적 휴머노이드 + 보행 애니메이션
  game/Effects.ts      트레이서·탄흔·스파크·혈흔 (전부 풀링)
  game/AudioEngine.ts  WebAudio 합성 사운드 (오디오 파일 0개)
```

에셋 파일이 하나도 없습니다. 텍스처·모델·사운드를 전부 런타임에 생성하기 때문에
저장소가 가볍고, 첫 로딩에 네트워크 요청이 없습니다.

## 실행

```bash
pnpm install

# 터미널 1 — 권위 서버 (Durable Object 포함)
pnpm dev:server        # http://127.0.0.1:8787

# 터미널 2 — 클라이언트 (/api, /ws 는 8787로 프록시)
pnpm dev:client        # http://127.0.0.1:5173
```

브라우저 두 개를 열고 한쪽에서 **New match** → 코드 복사 → 다른 쪽에 입력하면 같은 방에
들어갑니다. 주소창의 `#코드` 를 그대로 공유해도 됩니다.

서버만 따로 검증하려면:

```bash
pnpm smoke     # 이동 / 사격 / 히트 판정 / 스냅샷 흐름을 실제 소켓으로 확인
```

## 배포 (지금 바로 멀티하려면)

Worker 하나가 정적 파일과 게임 서버를 모두 담당합니다(`wrangler.jsonc` 의 `assets` 바인딩).
배포하면 `https://webgame.<서브도메인>.workers.dev` 주소가 나오고, 그 주소가 곧 게임입니다.

```bash
pnpm install
npx wrangler login        # 브라우저에서 한 번만 승인
pnpm deploy               # 클라이언트 빌드 + Worker 배포
```

계정 없이 바로 띄워보고 싶으면 로그인을 건너뛸 수도 있습니다 (임시 프리뷰 계정, 일정 시간 후 만료):

```bash
pnpm --filter @webgame/client build
cd apps/server && npx wrangler deploy --temporary
```

Durable Object 마이그레이션은 `v1` 태그로 정의돼 있고, SQLite 백엔드라 무료 플랜에서도 동작합니다.

### 휴대폰만으로 배포하기

터미널 없이 브라우저만으로 됩니다. 둘 중 하나만 하면 됩니다.

**방법 A — Cloudflare 대시보드에서 GitHub 연결 (추천, 시크릿 불필요)**

1. `dash.cloudflare.com` 접속 → 로그인/가입 (무료 플랜으로 충분합니다)
2. **Compute (Workers)** → **Create** → **Import a repository** → GitHub 연결 → 이 저장소 선택
3. 브랜치: `claude/multiplayer-fps-game-nxohcu`
4. 빌드 설정을 아래처럼 넣습니다 — 모노레포라 기본값 그대로는 안 됩니다.

   | 항목 | 값 |
   | --- | --- |
   | Root directory | `/` (비워두기) |
   | Build command | `pnpm install && pnpm --filter @webgame/client build` |
   | Deploy command | `npx wrangler deploy --config apps/server/wrangler.jsonc` |

5. **Save and Deploy**. 끝나면 `https://webgame.<서브도메인>.workers.dev` 주소가 나옵니다.

이후로는 이 브랜치에 푸시할 때마다 Cloudflare가 알아서 다시 배포합니다.

**방법 B — GitHub Actions (`.github/workflows/deploy.yml` 이미 들어있음)**

1. `dash.cloudflare.com` → 오른쪽 위 프로필 → **API Tokens** → **Create Token**
   → **Edit Cloudflare Workers** 템플릿 → 생성된 토큰 복사
2. 같은 대시보드 Workers 페이지 오른쪽에서 **Account ID** 복사
3. GitHub 저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
   - `CLOUDFLARE_API_TOKEN` = 1번 토큰
   - `CLOUDFLARE_ACCOUNT_ID` = 2번 ID
4. **Actions** 탭 → *Deploy to Cloudflare* → **Run workflow**

이후 푸시할 때마다 타입체크 → 빌드 → 배포가 자동으로 돌아갑니다.

### 배포 후 같이 하는 법

1. 나온 주소를 열면 **Live servers** 목록이 뜹니다. 사람이 있는 방이 위로 올라오고,
   초록 점이 켜진 방은 지금 누가 하고 있다는 뜻입니다. 아무 줄이나 누르면 들어갑니다.
2. 그냥 **Quick match** 를 눌러도 됩니다 — 가장 붐비는 빈자리 있는 방으로 넣어줍니다.
   둘이 각자 눌러도 같은 방에서 만납니다.
3. 빈 자리는 봇이 채우고, 사람이 들어오면 봇이 빠집니다. **Options → Bots: Off** 로
   봇 없는 방을 만들 수도 있습니다(빈 방에 처음 들어간 사람 설정이 그 방에 적용됩니다).
4. 특정 방을 지정하려면 주소창의 `#ARENA` 링크를 공유하거나 **Join by match code** 사용.
5. 서버 없이 혼자 감을 잡고 싶으면 **Solo vs bots** — 브라우저 안에서 같은 서버 코드를
   그대로 돌립니다.

## 넷코드

권위는 전적으로 서버에 있습니다. 클라이언트는 예측만 하고, 어긋나면 조용히 보정됩니다.

1. **입력 (클라이언트 → 서버)** — 클라이언트는 64Hz 고정 스텝으로 입력을 만들고,
   `seq` 를 붙여 40Hz로 묶어 보냅니다. 같은 입력으로 로컬 시뮬레이션을 즉시 돌리므로
   조작 지연이 0입니다.
2. **시뮬레이션 (서버)** — DO가 64Hz로 `simulateMovement()` 를 돌립니다.
   클라이언트와 **완전히 동일한 코드**(`packages/shared`)라서 예측이 어긋날 이유가 없습니다.
3. **스냅샷 (서버 → 클라이언트)** — 32Hz. 플레이어당 26바이트(위치 f32, 각도 i16,
   속도 i16, 플래그·체력·무기 u8). 각 클라이언트는 자기 입력의 `ack seq` 를 함께 받습니다.
4. **재조정** — 스냅샷을 받으면 서버 상태로 되돌린 뒤, 아직 ack되지 않은 입력을 다시
   적용합니다. 남은 오차는 렌더 좌표에 얹어 지수 감쇠시켜서 순간이동처럼 보이지 않게 합니다.
5. **보간** — 다른 플레이어는 100ms 과거를 렌더링합니다. 스냅샷 사이를 항상 보간하므로
   끊김 없이 움직입니다.
6. **지연 보상** — 서버는 1초치 위치 히스토리를 들고 있다가, 발사 시점에
   `RTT/2 + 보간지연` 만큼 세계를 되감아 히트박스를 복원하고 레이캐스트합니다.
   되감기는 250ms로 상한이 걸려 있어 고핑 남용을 막습니다.
7. **탄퍼짐 결정성** — 스프레드 난수는 `(playerId, shotSeq)` 시드의 PRNG라서
   클라이언트가 그린 트레이서와 서버 판정이 같은 방향을 씁니다.

치트 방어: 이동은 서버가 계산하고, 탄약·연사·재장전·데미지 전부 서버 권위입니다.
클라이언트가 보내는 건 조작 입력과 시점각뿐입니다.

## 설정

모든 설정은 하나의 스키마(`ui/SettingsPanel.ts`)로 정의돼 있고, 메인 메뉴와 인게임
오버레이가 같은 스키마를 렌더링합니다. 설정 하나를 추가하려면 항목 한 줄만 쓰면 됩니다.
게임 중에는 `Esc` 로 열리며, 서버가 소유하는 값(봇 수·난이도)을 뺀 나머지는 전부
**즉시 반영**됩니다.

| 그룹 | 항목 |
| --- | --- |
| Mouse | 감도, 조준(ADS) 감도 배수, 스무딩, 상하 반전 |
| View | 시야각(70~110°), 밝기, 무기 스웨이, 화면 흔들림 |
| Audio | 볼륨, 음소거 |
| Crosshair | 색상, 중앙 점, 탄퍼짐 연동 |
| Match | 봇 수(0~8), 난이도 4단계, 시작 무기 |
| Graphics | 품질 3단, 해상도, 동적 해상도, 필름 그레인·비네트 |
| HUD | 지도 표시, 성능 표시 |

## 봇 난이도

난이도는 0~1 스칼라가 아니라 **티어 테이블**입니다. 스칼라 하나로는 "느리고 + 부정확하고
+ 눈치 없는" 상태를 표현할 수 없어서, 실제로 승부를 가르는 값들을 전부 명시했습니다.

| | Rookie | Regular | Veteran | Elite |
| --- | --- | --- | --- | --- |
| 반응 시간 (최초 발견) | 620~820ms | 380~520ms | 240~340ms | 140~220ms |
| 재조준 반응 | 400~520ms | 240~340ms | 150~220ms | 90~140ms |
| 조준 회전 속도 | 2.1 rad/s | 3.2 | 4.6 | 6.5 |
| 조준 오차 원뿔 | ±5.2° | ±3.2° | ±1.8° | ±1.0° |
| 시야각 | ±50° | ±65° | ±85° | ±110° |
| 시야 거리 | 28m | 40m | 60m | 90m |
| 적 위치 지연 | 220ms | 150ms | 90ms | 45ms |
| 의도적 미스 | 35% | 15% | 5% | 0% |

특히 중요한 세 가지:

- **봇도 지연된 정보를 봅니다.** 예전에는 서버의 실시간 좌표를 그대로 읽었습니다.
  사람은 원격 플레이어를 100ms 과거로 보간해서 보는데(거기에 자기 핑까지) 봇만 현재를
  봤으니, 어떤 사람도 가질 수 없는 정보 우위였습니다. 지금은 히트 판정에 쓰던 위치
  히스토리에서 티어별 지연만큼 과거를 샘플링합니다.
- **시야각이 생겼습니다.** 예전에는 레이캐스트만 했기 때문에 등 뒤에 서 있어도 즉시
  발견하고 돌아섰습니다. 측면·후방 기습이 성립하지 않았습니다.
- **엄폐가 통합니다.** 예전에는 시야가 끊겨도 상대의 현재 좌표로 계속 경로를 잡았습니다
  (사실상 벽 너머 추적). 지금은 **마지막으로 본 위치**로 이동하고, 4초가 지나면 포기합니다.

| 하늘 | 단색 배경 | 물리 하늘 | 물리 하늘 |
| 조명 | 태양 + IBL | + 고정 조명 5개 | + 고정 조명 5개 |
| 픽셀 비율 상한 | 1.0 | 1.25 | 2.0 |

소프트웨어 렌더러(SwiftShader) 기준으로 측정했을 때 Low가 High 대비 **약 5배** 빨랐습니다.
여기에:

- **Resolution 슬라이더** (50~100%) — 낮은 해상도로 그리고 업스케일합니다.
- **동적 해상도** — 프레임 타임을 보고 해상도를 자동으로 오르내립니다. 픽셀 수에 비례해
  비용이 드니 보정은 제곱근으로 계산하고, 판단은 프레임 카운터가 아니라 **벽시계** 기준으로
  합니다(느린 기기일수록 프레임 기준 평균은 수렴이 느려서 정작 필요할 때 반응하지 못합니다).
- HUD 좌측 상단에 실제 FPS와 현재 렌더 스케일이 표시됩니다.

## 지도

우측 상단 미니맵은 서버가 충돌 판정에 쓰는 것과 **같은 브러시 데이터**로 그려지므로 실제
지형과 어긋날 수 없습니다. `M` 으로 끄기 / 작게 / 크게를 오갑니다.

적 위치를 상시 표시하지는 않습니다(그건 사실상 월핵입니다). 대신 **총을 쏜 위치가 핑으로
찍히고** 서서히 사라집니다 — 교전 위치를 찾는 데는 그게 더 유용합니다.

## 그래픽

- ACES 필믹 톤매핑, 절차적 하늘 + 범위가 제한된 그라디언트 IBL
- 태양광 그림자맵(플레이어를 따라다니는 타이트한 프러스텀)
- 절차적 PBR 텍스처 — 알베도/러프니스/노멀을 노이즈 + 소벨로 생성
- 블룸, SMAA, 필름 그레인 + 비네트 + 미세 색수차
- 1인칭 무기는 별도 씬/카메라로 렌더 — 벽에 파고들지 않고, 시야각도 따로 씁니다
- 품질 프리셋 3단(Low / Medium / High) — 메뉴에서 변경, `localStorage` 에 저장

> IBL을 만들 때 물리 하늘을 그대로 프리필터하면 태양 원반 값이 half-float 범위를 넘어
> Inf/NaN이 되고, 그게 블룸 블러를 타고 화면 전체를 검게 만듭니다. 그래서 환경맵은
> 값이 제한된 그라디언트로 직접 굽습니다 (`Renderer.ts` 의 `buildSkyEnvTexture`).
